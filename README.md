# Blogging API

REST API for a blogging platform: user registration and login, password reset, private blog management (create, edit, delete) and a **public** blog feed.

**Stack:** Node.js (>= 20) · Express 4 · TypeScript (strict) · Prisma 6 · PostgreSQL · Zod 4 · JWT (httpOnly cookie)

## Quick start

```bash
# 1. Install dependencies
npm install

# 2. Create your env file, then edit DATABASE_URL and JWT_SECRET
cp .env.example .env

# 3. Start PostgreSQL (or use your own server)
docker compose up -d

# 4. Create the tables from prisma/schema.prisma (also generates the Prisma client)
npx prisma migrate dev

# 5. Run the server (auto-reloads on file changes)
npm run dev
```

The API is now on **http://localhost:3000**.

| URL | What |
|---|---|
| `http://localhost:3000/api/v1/health` | Health check |
| `http://localhost:3000/api-docs` | Swagger UI (try every endpoint in the browser) |
| `http://localhost:3000/api-docs.json` | Raw OpenAPI document (import into Postman / Insomnia) |

> **Prisma does not start the server.** Prisma creates tables and the typed database client; the server is started with `npm run dev` (development) or `npm run build && npm start` (production). Run `npx prisma generate` whenever `schema.prisma` changes (the migrate and db push commands below already do it).

## Environment variables

Copy `.env.example` to `.env`. Values are validated with Zod at startup ([src/configs/env.ts](src/configs/env.ts)); the server refuses to start if one is invalid.

| Variable | Required | Default | Description |
|---|---|---|---|
| `DATABASE_URL` | yes | | PostgreSQL URL, e.g. `postgresql://postgres:postgres@localhost:5432/blogging?schema=public`. Must start with `postgresql://` or `postgres://` |
| `JWT_SECRET` | yes | | Secret used to sign login tokens. **At least 32 characters** |
| `NODE_ENV` | no | `development` | `development`, `test` or `production` |
| `PORT` | no | `3000` | HTTP port |
| `JWT_EXPIRES_IN` | no | `1d` | Login token lifetime (also the cookie lifetime) |
| `COOKIE_NAME` | no | `access_token` | Name of the httpOnly session cookie |
| `BCRYPT_SALT_ROUNDS` | no | `12` | Password hashing cost (10 to 15) |
| `CORS_ORIGIN` | no | `*` | Allowed origin(s), comma-separated. Set your frontend origin in production |
| `RESET_TOKEN_EXPIRES_MIN` | no | `60` | Password reset link lifetime in minutes |
| `RESET_PASSWORD_URL` | no | `http://localhost:5173/reset-password` | Frontend page the reset link points to (`?token=...` is appended) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` | no | port `587` | SMTP server for emails. **If `SMTP_HOST` is empty, reset links are printed to the server console (development only)** |
| `MAIL_FROM` | no | `Blogging <no-reply@blogging.local>` | Sender of emails |

## How the layers connect

### Start-up chain

```
server.ts ── connectDatabase() ──► configs/database.ts ──► PrismaClient ──► PostgreSQL
    │
    └── createApp() ──► app.ts
                          ├─ /api-docs, /api-docs.json      (configs/swagger.ts)
                          ├─ helmet, cors, express.json, cookie-parser, morgan
                          ├─ rate limiters
                          ├─ /api/v1 ──► routes/index.ts ──► auth | blogs | public routes
                          ├─ notFoundHandler                (middleware/error.ts)
                          └─ errorHandler                   (middleware/error.ts)
```

### One request, end to end

Example: `POST /api/v1/blogs` (create a blog)

```
HTTP request
  │
  ▼
app.ts ................ helmet -> cors -> json body -> cookie-parser -> logger
  │
  ▼
routes/index.ts ....... "/blogs" -> blog.routes.ts
  │
  ▼
blog.routes.ts ........ authenticate  ->  validate(createBlogSchema)  ->  createBlog
  │                      (middleware)      (validators/blog.validator)     (controller)
  ▼
blog.controller.ts .... reads req.auth + req.body, calls the service
  │
  ▼
blog.service.ts ....... business rules, converts database errors to ApiError
  │
  ▼
blog.model.ts ......... prisma.blog.create(...)        (the only place Prisma is used)
  │
  ▼
configs/database.ts ... shared PrismaClient  ──►  PostgreSQL table "blogs"
                                                   (defined by prisma/schema.prisma)
  │
  ▼
back up the chain ..... controller -> sendSuccess() -> { success, message, data }
                        any error -> next(error) -> middleware/error.ts -> JSON error
```

### Layer rules

| Layer | May use | Must not |
|---|---|---|
| `routes` | middleware, validators, controllers | contain logic |
| `controllers` | services, types, `utils/response` | touch Prisma or `req.body` shape directly (types come from validators) |
| `services` | models, utils | know about `req` / `res` |
| `models` | Prisma (`configs/database`) | contain business rules |
| `validators` | Zod only | import from other layers |

### Where each feature lives

| Feature | Route | Validator | Controller | Service | Model |
|---|---|---|---|---|---|
| Auth and password reset | `auth.routes.ts` | `auth.validator.ts` | `auth.controller.ts` | `auth.service.ts` | `user.model.ts`, `passwordReset.model.ts` |
| My blogs and the signed-in feed | `blog.routes.ts` | `blog.validator.ts` | `blog.controller.ts` | `blog.service.ts` | `blog.model.ts` |
| Public blogs | `public.routes.ts` | `blog.validator.ts` | `public.controller.ts` | `public-blog.service.ts` | `blog.model.ts` |

### Type safety

`prisma/schema.prisma` -> generated Prisma types -> `types/*` -> services and controllers.
Request shapes come from the Zod schemas (`z.infer`), so the validation rules and the TypeScript types can never disagree.

## API reference

Base URL: `http://localhost:3000/api/v1`

Every JSON response uses one envelope:

```jsonc
// success
{ "success": true, "message": "Blog created", "data": { ... } }
// failure
{ "success": false, "message": "Validation failed", "errors": [{ "path": "title", "message": "..." }] }
```

**Auth column:** `Public` = no login · `Login` = needs the session cookie (or `Authorization: Bearer <token>`).

### Auth

| Method | Endpoint | Auth | Description | Success |
|---|---|---|---|---|
| `POST` | `/auth/register` | Public | Create an account and sign in. Sets the session cookie | `201` `{ user }` |
| `POST` | `/auth/login` | Public | Sign in with email and password. Sets the session cookie | `200` `{ user }` |
| `POST` | `/auth/logout` | Public | Clear the session cookie | `200` |
| `GET` | `/auth/me` | Login | Get the signed-in user's profile | `200` user |
| `POST` | `/auth/forgot-password` | Public | Email a password reset link. Always returns `200`, whether or not the email exists (no account enumeration) | `200` |
| `POST` | `/auth/reset-password` | Public | Set a new password with the emailed token (single use) | `200` |

Request bodies

| Endpoint | Fields |
|---|---|
| `/auth/register` | `name` (2-100), `email`, `password` (8-72, with a lowercase, an uppercase and a digit), `confirmPassword` (must match), `age` (13-120) |
| `/auth/login` | `email`, `password` |
| `/auth/forgot-password` | `email` |
| `/auth/reset-password` | `token`, `password` (same rules as register), `confirmPassword` |

Errors: `409` email already registered · `401` wrong email or password · `400` invalid or expired reset token · `422` validation failed.

### Blogs (login required)

| Method | Endpoint | Auth | Description | Success |
|---|---|---|---|---|
| `POST` | `/blogs` | Login | Create a blog | `201` blog |
| `GET` | `/blogs` | Login | List blogs with search, sort, filter by blogger and pagination. Everyone's posts by default; `mine=true` for your own | `200` `{ items, meta }` |
| `GET` | `/blogs/:id` | Login | Read one blog (any signed-in user can read any blog) | `200` blog |
| `PATCH` | `/blogs/:id` | Login (author) | Edit title and/or content | `200` blog |
| `DELETE` | `/blogs/:id` | Login (author) | Delete a blog | `200` |

- **Body (`POST`, `PATCH`):** `title` (3-200), `content` (1-50 000, Markdown). For `PATCH` send at least one of them.
- **Ownership:** only the author can edit or delete. Someone else's blog (or a missing one) returns `404`.
- Each blog includes `author: { id, name }`.

`GET /blogs` query parameters

| Param | Default | Description |
|---|---|---|
| `q` | | Search in title and content (case-insensitive) |
| `author` | | Filter by blogger name (case-insensitive, partial match) |
| `sort` | `createdAt` | `createdAt`, `updatedAt`, `title` or `author` |
| `order` | `desc` | `asc` or `desc` |
| `mine` | `false` | `true` = only my own posts |
| `page` | `1` | Page number (>= 1) |
| `limit` | `10` | Page size (1-50) |

Response: `{ items: [...], meta: { page, limit, total, totalPages } }`

### Public blogs (no login)

| Method | Endpoint | Auth | Description | Success |
|---|---|---|---|---|
| `GET` | `/public/blogs` | Public | List all blogs with the author name and publish date. Search by blogger, sort and paginate | `200` `{ items, meta }` |
| `GET` | `/public/blogs/:id` | Public | Read one full blog (Markdown) | `200` blog |

`GET /public/blogs` query parameters

| Param | Default | Description |
|---|---|---|
| `author` | | Search by blogger name (case-insensitive, partial match) |
| `sort` | `publishedAt` | `publishedAt`, `title` or `author` |
| `order` | `desc` | `asc` or `desc` |
| `page` | `1` | Page number (>= 1) |
| `limit` | `10` | Page size (1-50) |

Public list item: `{ id, title, excerpt, author: { name }, publishedAt }`
Public detail: `{ id, title, content, author: { name }, publishedAt, updatedAt }`

Public responses deliberately contain **only the author's name**, never an email, author id or other internals. Posts that tie on the sort value come out newest first.

### System

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `GET` | `/health` | Public | Returns `{ success: true, message: "ok" }` |
| `GET` | `/api-docs` (outside `/api/v1`) | Public | Swagger UI |
| `GET` | `/api-docs.json` (outside `/api/v1`) | Public | OpenAPI JSON |

## Database and Prisma commands

### Models

| Model | Table | Purpose | Relations |
|---|---|---|---|
| `User` | `users` | Accounts (`name`, unique `email`, hashed `password`, `age`) | has many `Blog` and `PasswordResetToken` |
| `Blog` | `blogs` | Posts (`title`, `content`, `authorId`) | belongs to `User`, deleted with the user |
| `PasswordResetToken` | `password_reset_tokens` | Hashed, single-use reset tokens | belongs to `User`, deleted with the user |

### Create a new table

1. **Add a model** to `prisma/schema.prisma`, for example:

   ```prisma
   model Comment {
     id        String   @id @default(uuid())
     body      String
     blogId    String
     authorId  String
     createdAt DateTime @default(now())

     blog   Blog @relation(fields: [blogId], references: [id], onDelete: Cascade)
     author User @relation(fields: [authorId], references: [id], onDelete: Cascade)

     @@index([blogId])
     @@map("comments")
   }
   ```

   Also add the reverse side (`comments Comment[]`) to `Blog` and `User`.

2. **Create the migration and the table** (recommended, keeps a history in `prisma/migrations/`):

   ```bash
   npx prisma migrate dev --name add_comments
   # or: npm run prisma:migrate -- --name add_comments
   ```

   This creates the SQL migration, applies it to your database, and regenerates the Prisma client.

3. **Use it in code**, following the layers: a `comment.model.ts`, `comment.service.ts`, `comment.controller.ts`, `comment.validator.ts` and `comment.routes.ts`, then mount the routes in `src/routes/index.ts`.

### Push the schema without a migration (prototyping)

```bash
npx prisma db push
```

Makes the database match `schema.prisma` immediately and regenerates the client, but writes **no migration file**. Good for quick experiments; use `migrate dev` for anything you will deploy.

### All schema commands

| Command | When to use |
|---|---|
| `npx prisma migrate dev --name <name>` | Local development: create and apply a migration (also creates the database if it does not exist) |
| `npx prisma db push` | Quick prototyping: sync the schema with no migration file |
| `npx prisma generate` | Regenerate the typed client (after pulling schema changes or a fresh `npm install`) |
| `npx prisma migrate deploy` | **Production / CI**: apply existing migrations, never creates new ones |
| `npx prisma migrate status` | Show which migrations are applied |
| `npx prisma migrate reset` | **Deletes all data**, re-applies every migration (development only) |
| `npx prisma studio` | Open the database browser at http://localhost:5555 |
| `npx prisma format` | Format `schema.prisma` |
| `npx prisma validate` | Check `schema.prisma` for errors |

### Add data

Prisma Studio and the API are the two ways to add data.

- **Prisma Studio:** `npx prisma studio`, pick a table, click **Add record**.
- **Through the API:** register a user, then create blogs (see the [API reference](#api-reference)).
- **Bulk seed (optional, not included in this repo):** create `prisma/seed.ts`, for example:

  ```ts
  import { PrismaClient } from '@prisma/client';
  import bcrypt from 'bcryptjs';

  const prisma = new PrismaClient();

  async function main() {
    const user = await prisma.user.upsert({
      where: { email: 'demo@example.com' },
      update: {},
      create: { name: 'Demo User', email: 'demo@example.com', age: 25, password: await bcrypt.hash('Passw0rd!', 12) },
    });
    await prisma.blog.create({ data: { title: 'Hello world', content: 'My first post', authorId: user.id } });
  }

  main().finally(() => prisma.$disconnect());
  ```

  Register it in `package.json` (`"prisma": { "seed": "tsx prisma/seed.ts" }`), then run `npx prisma db seed`.

## Authentication

- Register and login set an **httpOnly** session cookie (`access_token` by default; `Secure` in production, `SameSite=Lax`). The token is **not** returned in the response body, so scripts cannot read it.
- For non-browser clients, send `Authorization: Bearer <token>` instead. The cookie is checked first.
- Passwords are hashed with bcrypt. Reset tokens are random, stored only as a SHA-256 hash, single use, and expire after `RESET_TOKEN_EXPIRES_MIN`.
- `POST /auth/logout` clears the cookie.
- If the account behind a valid token has been deleted, the API answers `401 Account no longer exists`.

## Errors and rate limits

| Status | Meaning |
|---|---|
| `400` | Bad request (malformed JSON, invalid or expired reset token) |
| `401` | Not signed in, bad credentials, or token invalid or expired |
| `404` | Not found (also used for blogs you do not own, so ids cannot be probed) |
| `409` | Conflict (email already registered) |
| `422` | Validation failed; `errors` lists each field |
| `429` | Rate limit exceeded |
| `500` / `503` | Unexpected error / database unavailable (details are logged, never sent to the client) |

| Limit | Scope |
|---|---|
| 5 requests / 15 min / IP | `POST /auth/forgot-password` |
| 100 requests / 15 min / IP | `/auth/*` |
| 120 requests / min / IP | `/public/*` |

## Troubleshooting

| Problem | Fix |
|---|---|
| `the URL must start with the protocol postgresql://` | Your `DATABASE_URL` has a prefix such as `postgresql+asyncpg://`. Use plain `postgresql://` |
| `Database "blogging" does not exist` | Run `npx prisma migrate dev`; it creates the database and the tables |
| `JWT_SECRET must be at least 32 characters` | Set a longer secret in `.env` |
| `Port 3000 is already in use` | Stop the other process or change `PORT` |
| `Property ... does not exist on type PrismaClient` | Run `npx prisma generate` after changing `schema.prisma` |
| No password reset email | Without `SMTP_HOST` the link is printed in the server console (development only) |
